## Vérifications et problèmes identifiés

- Vérification finale du moteur/serveur : `npm test`, **36 tests réussis** (29 moteur, 7 serveur).
- Vérification navigateur : trois parcours réussis dans la dernière suite ; le parcours distant a ensuite réussi isolément en 36,9 s, après correction de l'observation de son reçu transitoire. Les quatre scénarios sont validés sur la même release.
- `npm run build` et `npm run typecheck` réussis ; release servie : `.releases/2026-10-05T20-39-02-353Z-217863`. `git diff --check` propre.
- Captures avant changement dans `baseline/` ; nouvelles captures dans `screenshots/`. Le terminal garde désormais son graphique entier au-dessus du ticket sur grand écran ; le carrousel Contexte montre aussi le revenu des sociétés.
- HTTPS et `/health` vérifiés : [jouer](https://global-fund-next.213.199.40.67.sslip.io/). Services Next et historique actifs ; **157 fichiers historiques et les deux configurations d'infrastructure contrôlés, aucun changement** ([preuve](docs/reference-integrity-check.json)).
- Le rendu logiciel SwiftShader coûte davantage qu'un GPU réel : budget adaptatif, cache du terrain, pause hors onglet et mode réduit ; aucun résultat 60 FPS universel revendiqué.
- Diagnostic de rendu : ANGLE/SwiftShader, WebGL 2, canvas 1635×762 en viewport 1920×1080, ticker actif et cache sans recalcul continu. Le démarrage donne 0–1 FPS ; après chauffe, les variantes de cache donnent 6–9 FPS. La mesure officielle sépare cette chauffe du régime normal. Les essais sur GPU réel restent nécessaires.
- Mesure finale après **15 s de chauffe** : qualité haute à 1920×1080, **8 FPS RAF navigateur / 7 FPS plateau** sur 3006 ms ; qualité basse avec mouvements réduits à 1440×900, **60 FPS RAF / ticker plateau arrêté** sur 3005 ms. Ce sont des résultats SwiftShader, pas des mesures GPU ni une promesse de 60 FPS en jeu normal.
- Les maquettes regroupent les continents autrement que le jeu validé. Conservation de ses cinq zones pour préserver les règles et sauvegardes.
- Un build simultané a supprimé des anciens chunks pendant les captures. Le build utilise désormais un stage et une release ; validation exécutée sur une version stable.
- Captures et E2E WebGL sont séquencés pour éviter la contention du rendu logiciel. Le reçu d'achat est observé dans le DOM dès son insertion ; sa durée de 3,2 secondes reste inchangée.
- Les sons retenus sont des effets d'interface/plateau, pas des enregistrements dédiés d'une salle de marché.
